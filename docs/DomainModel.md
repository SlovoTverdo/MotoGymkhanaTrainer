# Domain Model

## 1. ExerciseDefinition

Переиспользуемый шаблон упражнения в собственной локальной 2D-системе координат.

Содержит:
- `id`, `name`, `version`;
- геометрический центр/локальный origin;
- `bounds`: базовая длина и ширина;
- `cones[]`: позиции и типы/цвета конусов;
- `markings[]`: дополнительная цветовая разметка;
- `ports[]`: точки входа/выхода с направлением касательной;
- `trajectory[]`: локальная опорная траектория;
- `checkpoints[]`: необязательные контрольные ворота.

Координаты объектов задаются относительно локального origin элемента.

### Ports

Порт содержит:
- идентификатор;
- роль (`entry`, `exit` или универсальная);
- локальную позицию;
- нормализованное направление касательной.

Направление обязательно: оно используется при автоматическом построении гладкого соединения между упражнениями.

## 2. ExerciseInstance

Размещение шаблона элемента на конкретной трассе.

Содержит:
- `instanceId`;
- ссылку на definition/template во внутреннем проекте редактора;
- мировую позицию;
- поворот;
- независимый масштаб `scaleX`, `scaleY`;
- выбранные entry/exit ports.

Масштабирование относится только к геометрии размещения элемента на данной трассе и не изменяет исходный шаблон.

При масштабировании изменяются позиции:
- конусов;
- линий/точек разметки;
- входов и выходов;
- траектории;
- checkpoints;
- bounds.

НЕ масштабируются физические размеры самих конусов и толщина линий.

Порядок преобразования локальной точки:
1. независимый scale X/Y;
2. rotation;
3. translation в мировые координаты площадки.

## 3. Connector

Автоматически или вручную построенное соединение между `ExitPort` одного элемента и `EntryPort` следующего.

Предпочтительная модель: cubic Bezier или Hermite spline.

Для cubic Bezier:
- P0 = exit position;
- P1 = exit position + exit tangent * control length;
- P2 = entry position - entry tangent * control length;
- P3 = entry position.

Editor автоматически предлагает control lengths, пользователь может корректировать соединение.

## 4. Track

Проект трассы в редакторе содержит:
- метаданные;
- параметры площадки;
- упорядоченный список `ExerciseInstance`;
- `Connector[]`;
- пользовательские корректировки.

## 5. Exported Track Snapshot

Viewer не должен зависеть от библиотеки `ExerciseDefinition`.

При экспорте Editor вычисляет все transform'ы и формирует самодостаточный JSON snapshot:
- мировые координаты всех конусов;
- мировая разметка;
- итоговая траектория;
- checkpoints;
- опциональные сведения о границах элементов/metadata.

Изменение шаблона элемента в будущем не должно менять уже экспортированную старую трассу.
