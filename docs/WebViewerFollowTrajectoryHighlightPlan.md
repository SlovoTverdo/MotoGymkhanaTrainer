# Web Viewer Follow Trajectory Highlight Plan

# Follow Trajectory Highlight Iteration 1

## 1. Цель

Добавить специальное динамическое отображение глобальной траектории во время автоматического следования по трассе.

В режиме Follow:

* пройденная часть маршрута скрывается;
* ближайший участок впереди подсвечивается зелёным;
* затем зелёный цвет плавно переходит в обычный цвет траектории;
* более удалённый участок отображается обычным цветом;
* после этого траектория плавно затухает;
* далёкая непройденная часть маршрута скрывается.

В режимах Walk и Fly траектория продолжает отображаться целиком обычным способом.

---

## 2. Scope

Итерация относится только к GDScript Web Viewer:

```text
web-viewer/
```

Не изменять:

* основной C# Viewer;
* desktop-редакторы;
* Exercise Definition formatVersion 2;
* Venue Definition formatVersion 1;
* Track Project formatVersion 3;
* Exported Track formatVersion 4;
* структуру глобальной trajectory в JSON.

---

## 3. Режимы отображения

Renderer глобальной траектории должен поддерживать минимум два визуальных режима:

```text
FULL_ROUTE
FOLLOW_WINDOW
```

### FULL_ROUTE

Используется в:

* Walk;
* Fly.

Поведение:

* вся траектория видима;
* используется существующий основной цвет;
* сохраняются существующие ширина, материал и surface projection.

### FOLLOW_WINDOW

Используется только в Follow.

Поведение определяется текущей дистанцией RouteFollowController.

---

## 4. Зоны Follow window

Для каждого положения вдоль маршрута рассчитывается:

```text
relativeDistance =
    pointRouteDistance
    - currentRouteDistance
```

Зоны:

```text
relativeDistance < passedCutoff
    скрыто

около текущей позиции
    короткая переходная зона для предотвращения резкого обрыва сзади

0 ... highlightLength
    зелёная подсветка

highlightLength ... highlightTransitionEnd
    переход зелёный → основной цвет

highlightTransitionEnd ... normalPreviewEnd
    основной цвет

normalPreviewEnd ... fadeEnd
    плавное затухание прозрачности

relativeDistance > fadeEnd
    скрыто
```

---

## 5. Начальные параметры

Рекомендуемые параметры первой версии:

```text
behindFadeLength          = 0.75 m
highlightLength           = 6.0 m
highlightTransitionLength = 8.0 m
normalPreviewLength       = 12.0 m
forwardFadeLength         = 5.0 m
```

Итого впереди отображается примерно:

```text
31 m
```

Параметры должны быть централизованы и настраиваемы.

Не размещать одинаковые числовые значения независимо:

* в shader;
* в renderer;
* в Follow controller;
* в UI.

---

## 6. Поведение позади камеры

Пройденная траектория должна гаситься.

Чтобы избежать резкого визуального обрыва непосредственно под камерой, допускается короткое затухание позади:

```text
-currentBehindFade ... 0
```

Например:

```text
-0.75 ... 0 m
```

До этой зоны пройденный маршрут полностью прозрачен.

Не оставлять всю пройденную траекторию с пониженной яркостью.

---

## 7. Зелёная подсветка

Ближайшая часть впереди использует яркий зелёный цвет.

Начальное значение:

```text
Color(0.15, 1.0, 0.25, 1.0)
```

Точный оттенок может быть скорректирован под текущие материалы, но должен:

* хорошо различаться на фоне асфальта;
* не сливаться с обычным цветом trajectory;
* оставаться читаемым в Compatibility renderer;
* быть заметным на экране телефона;
* не создавать чрезмерное свечение.

Не использовать HDR-зависимую яркость как единственный способ подсветки.

---

## 8. Основной цвет

Обычная зона впереди использует тот же основной цвет, что и полная траектория в Walk/Fly.

Источник основного цвета должен быть общим.

Не создавать отдельный почти такой же цвет только для Follow, если это не требуется материалом.

---

## 9. Цветовой переход

Между зелёной и обычной зонами требуется плавная интерполяция:

```text
greenColor → baseTrajectoryColor
```

Переход рассчитывается по расстоянию вдоль маршрута, а не по:

* мировому расстоянию до камеры;
* индексу вершины;
* номеру sample point;
* экранной глубине.

Это важно на петлях и близко расположенных участках маршрута.

---

## 10. Переднее затухание

После обычной видимой зоны alpha плавно уменьшается:

```text
1.0 → 0.0
```

После конца fade zone траектория полностью скрыта.

Затухание должно быть плавным и не зависеть от плотности sampling.

---

## 11. Расстояние вдоль маршрута

Каждая вершина или элемент отображаемой геометрии должен иметь значение накопленного расстояния вдоль RoutePath.

Источник:

```text
RoutePath.cumulative_distances
```

Renderer и Follow controller должны использовать один и тот же метрический контракт.

Не рассчитывать вторую независимую таблицу расстояний по уже созданному mesh, если доступна RoutePath.

---

## 12. Соответствие геометрии RoutePath

Projected trajectory renderer может иметь больше вершин, чем RoutePath, из-за:

* толщины линии;
* боковых граней;
* соединений;
* стрелок;
* triangulation.

Каждой визуальной вершине следует назначить route distance той центральной точки, из которой она была построена.

Для интерполированных точек:

```text
routeDistance =
    lerp(segmentStartDistance, segmentEndDistance, t)
```

Левая и правая стороны полосы в одном поперечном сечении должны иметь одинаковую route distance.

---

## 13. Предпочтительный способ реализации

Предпочтительный вариант:

```text
один или небольшое количество MeshInstance3D
+
route distance в vertex attribute
+
Compatibility-compatible shader
```

Shader получает uniform:

```text
current_route_distance
```

и параметры визуальных зон.

Преимущества:

* mesh не перестраивается каждый frame;
* обновляется один uniform;
* плавный градиент;
* низкая стоимость при воспроизведении;
* одинаковое поведение при Play, Pause и Step.

---

## 14. Передача route distance в shader

Допустимые vertex attributes:

```text
UV2.x
CUSTOM0
vertex color channel
```

Выбор зависит от текущего ArrayMesh и возможностей используемой версии Godot Compatibility renderer.

Требования:

* не разрушить уже используемые UV;
* не потерять основной цвет;
* обеспечить достаточную точность для длины маршрута;
* задокументировать выбранный channel.

Если используется vertex color:

* не смешивать route distance с итоговым display color без чёткой схемы;
* убедиться, что материал не изменяет attribute неожиданно.

---

## 15. Shader logic

Концептуальная shader-функция:

```text
relativeDistance =
    vertexRouteDistance
    - currentRouteDistance
```

Далее вычисляются:

```text
visibilityAlpha
trajectoryColor
```

Задняя часть:

```text
relativeDistance <= -behindFadeLength
    alpha = 0
```

Задний переход:

```text
-behindFadeLength ... 0
    alpha = smoothstep(...)
```

Зелёная зона:

```text
0 ... highlightLength
    color = highlightColor
```

Цветовой переход:

```text
highlightLength
...
highlightLength + highlightTransitionLength
```

```text
color = mix(highlightColor, baseColor, t)
```

Обычная зона:

```text
baseColor
```

Переднее затухание:

```text
normalPreviewEnd ... fadeEnd
    alpha = 1 - smoothstep(...)
```

После fadeEnd:

```text
alpha = 0
```

Использовать плавные функции, не жёсткие ступенчатые сравнения там, где требуется градиент.

---

## 16. Compatibility renderer

Shader должен работать в Godot Web Compatibility renderer.

Не использовать без необходимости:

* Forward+-specific features;
* compute shaders;
* storage buffers;
* unsupported varying layouts;
* desktop-only rendering paths.

Shader должен быть проверен в Web export, а не только в desktop editor.

---

## 17. Прозрачность

Материал должен корректно работать с alpha.

Следует учитывать:

* transparent render pass;
* depth draw;
* сортировку прозрачности;
* пересечение близких частей trajectory;
* наложение на асфальт;
* z-fighting.

Сохранить существующий небольшой surface offset.

Не выключать depth test полностью, если это заставляет траекторию отображаться сквозь объекты.

---

## 18. Fallback

Если shader-вариант:

* не компилируется;
* не поддерживается Compatibility renderer;
* показывает некорректный alpha;
* теряет route distance;
* существенно ломает rendering;

реализовать fallback:

```text
CPU-generated visible route window
```

Fallback может:

* выбирать только точки текущего видимого диапазона;
* разбивать диапазон на короткие части;
* назначать vertex colors;
* перестраивать только Follow mesh при значимом изменении distance.

Не создавать отдельный `MeshInstance3D` на каждый отрезок длиной 0.25 м.

Предпочтительнее один ArrayMesh с vertex colors.

---

## 19. Частота CPU fallback updates

Если применяется CPU fallback, не обязательно перестраивать mesh каждый render frame.

Допустимо обновление:

```text
когда currentRouteDistance изменилась более чем на 0.1–0.25 m
```

Но:

* Step должен обновлять mesh немедленно;
* Restart должен обновлять немедленно;
* вход/выход из Follow должен обновлять немедленно;
* конец маршрута должен отображаться корректно.

---

## 20. Интеграция с RouteFollowController

Renderer получает текущее состояние через:

* signal;
* callback;
* read-only property;
* централизованную Viewer mode integration.

Предпочтительно RouteFollowController публикует:

```text
distance_changed(distance_meters)
playback_state_changed(...)
```

Но не следует испускать новый signal каждый frame, если текущая архитектура уже выполняет общий update.

Renderer не должен самостоятельно изменять RouteFollowController.

---

## 21. Play

При воспроизведении:

* зелёное окно плавно движется вперёд;
* пройденная часть исчезает;
* дальняя часть появляется только при приближении;
* не должно быть заметного скачка между sample points.

---

## 22. Pause

При Pause:

* визуальное окно остаётся неподвижным;
* пользователь может осматриваться;
* никакого мигания или восстановления полной trajectory не происходит.

---

## 23. Step Forward/Backward

При Step:

* окно немедленно перемещается на новое route distance;
* шаг назад снова показывает участок, который теперь находится впереди;
* ранее скрытый участок может снова стать видимым;
* логика не должна необратимо удалять пройденную геометрию.

Именно поэтому полное физическое удаление пройденных вершин не рекомендуется.

---

## 24. Restart

При Restart:

* зелёная зона возвращается в начало;
* вся дальняя часть снова скрыта;
* пройденная часть отсутствует;
* Play/Pause state сохраняется согласно текущей Follow policy.

---

## 25. Конец маршрута

При достижении конца:

* большая часть траектории позади скрыта;
* впереди почти нет видимой линии;
* оставшийся короткий участок плавно исчезает у конечной точки.

Допускается сохранить маленький финальный маркер.

Финальный маркер является optional и не блокирует итерацию.

Не показывать заново всю траекторию после завершения.

---

## 26. Вход в Follow

При входе:

1. переключить renderer в `FOLLOW_WINDOW`;
2. передать `route_distance = 0`;
3. применить параметры зон;
4. скрыть далёкую часть маршрута;
5. начать Follow playback.

Не должно быть одного frame, когда полная траектория остаётся видимой после входа в Follow.

---

## 27. Выход из Follow

При выходе:

1. вернуть renderer в `FULL_ROUTE`;
2. восстановить основной материал или shader mode;
3. показать всю траекторию;
4. не перестраивать Track и Venue;
5. не перезагружать JSON.

---

## 28. Track reload

При Track reload:

1. отключить старый Follow material state;
2. удалить старый trajectory mesh;
3. очистить route-distance attributes;
4. построить новый RoutePath;
5. построить новый trajectory mesh;
6. назначить новые cumulative distances;
7. установить режим FULL_ROUTE;
8. обновить доступность Follow.

Не сохранять старую дистанцию и старые shader uniforms.

---

## 29. Стрелки направления

В Iteration 1 стрелки можно обрабатывать одним из двух способов.

### Вариант A — скрыть в Follow

В Follow отображается только динамическая линия.

Это предпочтительный простой вариант, если существующие стрелки не поддерживают route distance.

### Вариант B — применять то же окно

Каждая стрелка получает route distance и:

* скрывается позади;
* окрашивается зелёным в ближайшей зоне;
* затухает впереди.

Это полезнее визуально, но требует дополнительной работы.

Минимальный обязательный scope:

```text
динамическая линия trajectory
```

Поддержка стрелок не должна блокировать итерацию.

Поведение стрелок должно быть явно указано в итоговом отчёте.

---

## 30. Маркер текущей позиции

Необязательный небольшой маркер может отображаться в точке:

```text
current route position
```

Но камера уже находится над этой точкой, поэтому маркер может быть плохо видим.

Не добавлять его, если он мешает обзору или усложняет прозрачность.

---

## 31. Мобильное отображение

Зелёная зона должна быть хорошо различима на маленьком экране.

Проверить:

* достаточную насыщенность;
* ширину линии;
* отсутствие чрезмерно тонкого fade;
* отсутствие мерцания при низком разрешении;
* landscape;
* portrait.

Не увеличивать толщину только в Follow без необходимости, если это создаёт заметный скачок при переключении режима.

Если нужна мобильная поправка толщины, она должна быть централизованной и минимальной.

---

## 32. Производительность

В shader-варианте каждый frame обновляется только:

```text
current_route_distance uniform
```

Не перестраивать:

* Venue;
* projected points;
* cumulative table;
* Track root;
* collision.

Не выполнять дополнительный physics raycast для подсветки.

---

## 33. Отладочная информация

В developer/debug режиме допускается показывать:

```text
current route distance
highlight end
normal preview end
fade end
render mode
```

В production UI это не требуется.

Не спамить browser console каждый frame.

---

## 34. Error handling

Если:

* RoutePath невалидна;
* trajectory mesh отсутствует;
* distance attribute не создан;
* shader material не готов;

Follow должен продолжить работать как движение камеры.

Допустимое fallback-поведение:

```text
полная trajectory обычным цветом
```

Показать сгруппированное diagnostic warning.

Ошибка визуализации не должна блокировать:

* Play;
* Pause;
* Step;
* Exit Follow.

---

## 35. Не реализовывать

В этой итерации не добавлять:

* curved markings;
* text markings;
* изменение JSON;
* текущие названия упражнений;
* подсветку отдельных Exercise;
* разноцветные зоны скорости;
* motorcycle simulation;
* checkpoints;
* lap timing;
* trail behind camera;
* permanent deletion пройденной геометрии;
* редактор параметров градиента;
* пользовательские настройки цветов;
* bloom-dependent rendering;
* серверное сохранение.

---

## 36. Definition of Done

Итерация завершена, если:

* Walk показывает полную trajectory;
* Fly показывает полную trajectory;
* Follow включает динамическое окно;
* пройденная часть скрывается;
* короткое затухание позади работает;
* ближайшая зона зелёная;
* зелёный плавно переходит в основной цвет;
* обычная зона впереди отображается;
* переднее затухание работает;
* дальняя trajectory скрыта;
* границы рассчитываются в метрах;
* используется RoutePath cumulative distance;
* скорость Follow не влияет на длины визуальных зон;
* Play плавно перемещает окно;
* Pause останавливает окно;
* Step Forward обновляет окно;
* Step Backward восстанавливает нужный участок;
* Restart возвращает окно в начало;
* конец маршрута отображается корректно;
* выход в Walk возвращает полную trajectory;
* выход в Fly возвращает полную trajectory;
* Track reload очищает старый визуальный state;
* отсутствие highlight renderer не ломает Follow;
* shader работает в Compatibility renderer либо реализован CPU fallback;
* Web export успешно создаётся;
* локальный HTTP Web Viewer запускается;
* GitHub Pages Viewer отображает подсветку.
